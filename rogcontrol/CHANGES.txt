ROG Control 1.0
===============

A G-Helper-style control panel for ASUS ROG laptops on Linux, without
needing asusctl. Power profiles, fan curves, CPU and GPU limits, charge
threshold and keyboard lighting, in one window with a tray icon.

What it does
------------

Profiles. Quiet, Balanced Power, Balanced Performance and Performance, plus
any you add. A profile carries CPU power limits, an undervolt, a turbo
switch, a maximum clock, an energy preference, GPU limits, and a fan curve
per fan. Switching profile applies all of it. The two Balanced profiles are
identical apart from how hard the CPU chases clocks.

Fans. An eight-point curve per fan, edited on a graph in real RPM rather than
percent, calibrated to your machine. Curves are re-asserted in the
background, because the embedded controller drops them whenever the power
mode changes.

CPU. STAPM, fast and slow power limits, temperature target, Curve Optimizer
undervolt, turbo boost on or off, and a maximum clock. The clock setting is
a ceiling, not a fixed speed: cores still drop to idle underneath it.

GPU. Power limit, core and memory clock offsets, a clock ceiling, NVIDIA
Dynamic Boost and temperature target.

Keyboard. Brightness, and lighting modes: Static, Breathing, Pulse, Colour
Cycle, Rainbow, Gradient Static, GPU and CPU temperature colour, Battery
Level, and Ambient, which follows what is on screen. Modes the hardware
cannot do are not offered.

Also. Charge threshold, AC/battery profile auto-switch, two-way sync with
the OS power mode, keyboard shortcuts for cycling profiles and lighting,
import/export of profiles, and a tray menu that switches profiles.

Notes from developing it on a G614PR
------------------------------------

Some of this took a lot of measuring, and is worth knowing if you are
chasing the same things:

  - The embedded controller reads a CPU temperature that Linux never
    exposes. It takes short excursions into the 85-90 C band several times a
    minute while k10temp sits at 58-60 C, and obeys your fan curve for that
    reading -- which looks exactly like the fans ignoring the curve. Nothing
    on the software side changes it: not the clock cap, turbo off, undervolt,
    power limits, energy preference, the GPU, or how often anything is
    polled. All measured, all ruled out. What does help is keeping the curve
    flat between roughly 68 and 88 C, so the excursions have nowhere to climb
    to.
  - The controller applies a fan curve only when pwm<N>_enable is written,
    and silently drops curve writes fired less than about eight seconds
    apart across channels.
  - This keyboard controller (0b05:19b6) renders multi-zone breathing as
    static colour at every speed, while single-zone breathing animates
    normally. Driving the fade in software is not an option either: a zone
    write takes 270 ms, which steps visibly instead of breathing.
  - Screen capture for Ambient goes through the desktop portal, the only
    route available on Wayland. Screenshots were measured at 1.5-5 seconds
    each and a 4 MB file per capture, so the mode streams instead.
