ROG CONTROL - FULL INSTALL GUIDE (FRESH CACHYOS)
===================================================
For: ASUS ROG Strix G614PR, Ryzen 9 8940HX, RTX 5070 Ti, CachyOS + GNOME
Covers: every dependency from a clean system, the app itself, and how
to remove everything if you ever want to.


PART 1 - SYSTEM PACKAGES
===========================

sudo pacman -Syu
sudo pacman -S python-gobject gtk3 libnotify base-devel git cmake \
               nvidia-utils supergfxctl

What each one is for:
  python-gobject, gtk3   - the GUI toolkit the app is written in
  libnotify              - lets the app show a desktop notification
                           when it switches profiles automatically
  base-devel, git, cmake - needed to build ryzenadj from source
  nvidia-utils           - provides nvidia-smi (GPU power/clock control)
  supergfxctl            - GPU mode switching (Hybrid/Integrated/dGPU)

Enable the GPU mode service:
    sudo systemctl enable --now supergfxd
    supergfxctl -g
This should print your current GPU mode. If it errors, supergfxd may
need a moment after first enable, or a reboot.


PART 2 - AUR HELPER (yay)
============================
CachyOS doesn't ship an AUR helper by default. Install one:

    cd /tmp
    git clone https://aur.archlinux.org/yay-bin.git
    cd yay-bin
    makepkg -si

(makepkg comes from base-devel, which you already installed in Part 1.)


PART 3 - AUR PACKAGES
=========================

    yay -S libappindicator-gtk3
    yay -S rogauracore-git

libappindicator-gtk3  - real system tray icon support
rogauracore-git       - keyboard RGB control; confirmed to support your
                        laptop's exact keyboard controller (USB ID
                        0b05:19b6, verified via `lsusb` on this machine)


PART 4 - RYZENADJ (build from source)
=========================================
Not reliably packaged, so this is built directly from FlyGoat's repo:

    rm -rf /tmp/RyzenAdj
    git clone https://github.com/FlyGoat/RyzenAdj.git /tmp/RyzenAdj
    cd /tmp/RyzenAdj
    mkdir build && cd build
    cmake .. -DCMAKE_BUILD_TYPE=Release
    make -j$(nproc)
    sudo cp ryzenadj /usr/local/bin/ryzenadj
    sudo chmod 755 /usr/local/bin/ryzenadj

Verify:
    sudo /usr/local/bin/ryzenadj -i

Expected on this CPU (Dragon Range / Ryzen 9 8940HX): it will say "no
compatible ryzen_smu kernel module found, fallback to /dev/mem" and
"Unable to init power metric table" -- both harmless. Those only affect
optional monitoring output; ryzenadj itself confirms actual power-limit
adjustments (--stapm-limit, --fast-limit, etc.) still work without them.
As long as it prints your CPU family and doesn't hard-error, it's good.


PART 5 - HARDWARE SANITY CHECKS
====================================
Before installing the app, confirm the sysfs paths it depends on
actually exist on this fresh install:

Fan curve control:
    for d in /sys/class/hwmon/hwmon*; do
        echo "$d: $(cat $d/name 2>/dev/null)"
    done
You need to see "asus_custom_fan_curve" (or equivalent) in this list.
If you don't, fan curves won't work and the exact hwmon driver/kernel
module situation needs checking before continuing.

Charge limit control:
    ls /sys/class/power_supply/BAT0/charge_control_end_threshold
If this file is missing, the charge-limit slider won't work.

Keyboard brightness:
    ls /sys/class/leds/asus::kbd_backlight/brightness
Should exist (this is separate from RGB, which goes through rogauracore
instead).


PART 6 - PRIVILEGED HELPER + SUDOERS
=========================================
The app itself never runs as root. Only one small, fixed script does,
and only for the specific hardware-writing commands it validates
internally.

    unzip ~/Downloads/rogcontrol-v5.zip -d ~/Downloads   # adjust path as needed
    cd ~/Downloads/rogcontrol

    sudo cp rogcontrol-helper /usr/local/bin/rogcontrol-helper
    sudo chown root:root /usr/local/bin/rogcontrol-helper
    sudo chmod 755 /usr/local/bin/rogcontrol-helper

Confirm your username, then add the sudoers rule:
    whoami

    echo "$(whoami) ALL=(root) NOPASSWD: /usr/local/bin/rogcontrol-helper" \
        | sudo tee /etc/sudoers.d/rogcontrol
    sudo chmod 440 /etc/sudoers.d/rogcontrol
    sudo visudo -c

visudo -c MUST say "parsed OK". If it reports an error, fix it before
doing anything else -- a broken sudoers file can break sudo entirely.

Why this design: the GUI runs as your normal user the whole time. Every
value it wants to write to hardware (CPU power limits, GPU power limit,
fan curve points, keyboard brightness, charge limit) is passed as a
plain argument to this one helper script, which independently validates
every value against a hard safe range before writing anything -- so
even if the GUI had a bug, this script is the actual safety backstop.


PART 7 - RUN THE INSTALLER
===============================

    ./install.sh

This will:
  - check all the dependencies above and tell you if anything's missing
  - install the app to ~/.local/bin/rogcontrol.py
  - install the icon (and remove any stale old icon file)
  - install the app-grid launcher ("ROG Control")
  - install the silent autostart entry (starts hidden in the tray at
    login, no window pop-up)
  - install the cycle-profile shortcut script (bindable to a hotkey)
  - install and enable two systemd --user services:
      rogcontrol-apply.service    - reapplies your saved profile once,
                                    shortly after login
      rogcontrol-enforcer.service - runs continuously in the background,
                                    re-enforcing your profile if the
                                    BIOS/firmware resets something


PART 8 - FIRST LAUNCH / VERIFICATION
=========================================
Launch it from the app grid (search "ROG Control"), or manually:

    python3 ~/.local/bin/rogcontrol.py

Check each tab:
  - CPU: adjust a slider, confirm no error appears
  - GPU: confirm the mode radio button matches what
    `supergfxctl -g` reports; try a small clock offset
  - Fans: drag a curve point, confirm the RPM readout responds; click
    the value label to toggle RPM/%; hit "Apply All Fan Curves"
  - Keyboard: brightness slider, then try RGB (Static color first --
    simplest to visually confirm)
  - Charge limit: check it reads/writes correctly

Confirm autostart is active:
    systemctl --user status rogcontrol-apply.service
    systemctl --user status rogcontrol-enforcer.service
Both should show "enabled" and (for the enforcer) "active (running)".

Log out and back in once to confirm the app starts silently in the
tray with no window popping up, and that your profile settings are
still applied after the fresh login.


PART 9 - WHAT RUNS AUTOMATICALLY AT STARTUP
================================================
Three things start at login, and it's worth knowing exactly what each
one does:

1. rogcontrol-apply.service
   Runs ONCE, shortly after login. Reapplies your last-active profile
   in full -- CPU power limits (stapm/fast/slow/temp/coall), GPU power
   limit and clock offsets, all three fan curves, keyboard brightness,
   and charge limit -- in one pass. This is a genuine force-apply: it
   doesn't check whether the hardware already matches your profile, it
   just writes all the values again every login.

2. rogcontrol-enforcer.service
   Starts at login too, but keeps running continuously afterward (it
   doesn't exit). It periodically re-checks and re-applies your profile
   in the background -- this is what catches the BIOS/firmware silently
   resetting something (e.g. after sleep/wake or unplugging the charger)
   and puts it back without you having to notice or do anything.

3. The GUI app itself (autostart entry)
   Also launches at login, but with --minimized, so it starts hidden in
   the tray -- no window pop-up. It doesn't do the actual hardware
   force-apply itself; the two services above handle that. The tray
   icon is just there so you can open the window or cycle profiles
   without hunting for it in the app grid.

So yes: every boot/login, your CPU profile and fan curves get force-
applied automatically, with no manual step needed -- that's the whole
point of this setup. If you ever want a particular boot to NOT auto-
apply (e.g. you're testing something manually and don't want it
overwritten), stop the two services first:

    systemctl --user stop rogcontrol-apply.service
    systemctl --user stop rogcontrol-enforcer.service

and re-enable them (or just reboot) when you want auto-apply back:

    systemctl --user enable --now rogcontrol-apply.service
    systemctl --user enable --now rogcontrol-enforcer.service


PART 10 - HOW TO FULLY REMOVE EVERYTHING
============================================
If you ever want to walk away from this cleanly:

    # Stop and remove the systemd --user services
    systemctl --user disable --now rogcontrol-apply.service
    systemctl --user disable --now rogcontrol-enforcer.service
    rm -f ~/.config/systemd/user/rogcontrol-apply.service
    rm -f ~/.config/systemd/user/rogcontrol-enforcer.service
    systemctl --user daemon-reload

    # Stop and remove the system-level shutdown hook service
    sudo systemctl disable --now rogcontrol-shutdown-hook.service
    sudo rm -f /etc/systemd/system/rogcontrol-shutdown-hook.service
    sudo systemctl daemon-reload

    # Remove the suspend/resume hook (not a systemd unit -- systemd calls
    # every executable script in this directory directly)
    sudo rm -f /etc/systemd/system-sleep/rogcontrol-sleep-hook.py
    sudo rm -f /usr/local/bin/rogcontrol-shutdown-hook.py

    # Kill the running app/tray if open
    pkill -f rogcontrol.py

    # Remove the app itself and its launchers/shortcut scripts
    rm -f ~/.local/bin/rogcontrol.py
    rm -f ~/.local/bin/rogcontrol-apply.py
    rm -f ~/.local/bin/rogcontrol-enforcer.py
    rm -f ~/.local/bin/rogcontrol-cycle-profile.py
    rm -f ~/.local/bin/rogcontrol-cycle-kbdlight.py
    rm -f ~/.local/bin/rogcontrol-adjust-kbdbrightness.py
    rm -f ~/.local/share/applications/rogcontrol.desktop
    rm -f ~/.local/share/applications/rogcontrol-cycle-profile.desktop
    rm -f ~/.config/autostart/rogcontrol-autostart.desktop
    rm -f ~/.local/share/icons/hicolor/256x256/apps/rogcontrol.png
    gtk-update-icon-cache ~/.local/share/icons/hicolor 2>/dev/null

    # Remove the privileged helper and sudoers rule
    sudo rm -f /usr/local/bin/rogcontrol-helper
    sudo rm -f /etc/sudoers.d/rogcontrol

    # Remove your saved profiles/config (this is a single flat file, not
    # a directory)
    rm -f ~/.config/rogcontrol.json

    # If you bound any custom keyboard shortcuts to the scripts above,
    # remove them too: GNOME Settings > Keyboard > Custom Shortcuts

    # Optional: remove ryzenadj
    sudo rm -f /usr/local/bin/ryzenadj

    # Optional: re-enable asusd if you disabled it from the app's System
    # tab and want it back
    sudo systemctl enable --now asusd.service

    # Optional: remove rogauracore and libappindicator (only if nothing
    # else on your system depends on them)
    yay -R rogauracore-git libappindicator-gtk3

That fully reverts your system to before this app existed. Your CPU/GPU
power limits, fan curves, and keyboard settings will stay at whatever
they were last set to (removing the app doesn't reset hardware state --
reboot if you want the BIOS defaults back).
